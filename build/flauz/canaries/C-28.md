## Steps (scripted boot + browser tool run)

1. Boot with verbose logging (recipe as C-20 §Steps-1).
2. Assert the boot-level surface (automated today): browserView contribution
   compiled in; sampled tool set greppable in `out/` (navigate/click/type/
   hover/drag/screenshot/runPlaywrightCode — ≥5 of 7 sampled).
3. **[driver — WAITING-ON-LANE F]** Ask the flauz participant to open a page
   via `navigateBrowserTool` and screenshot it.
4. **[driver — WAITING-ON-LANE F]** Assert the tool was *offered to and invoked
   by* the non-Copilot participant (tool-call progress part + screenshot part
   in the chat model).
5. **[driver — WAITING-ON-LANE F]** COLD measurement: from a fresh boot, time
   the first browser tool call end-to-end (request → screenshot part rendered).
6. **[driver — WAITING-ON-LANE F]** WARM measurement: repeat the same call
   immediately (shared process + Chromium warm).
7. Record both timestamps in the canary report; the cold-warm delta isolates
   the shared-process bring-up + Chromium spawn share of the path
   (§5.2 budget: ≤ 250 ms p95 overhead EXCLUDING those one-time costs).
8. Capture `ps` before/after for the 4-process path evidence (ext host,
   renderer, shared, Chromium) — the pane-renderer row of §3.2.
