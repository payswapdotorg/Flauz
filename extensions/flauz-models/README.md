# flauz-models

Flauz model vendor pack (Wave 3 Lane F). This built-in extension is the seed
of Flauz's model-provider fabric: it ships **one live, deterministic mock
vendor** (`flauz-mock`) plus **design-only stubs** for future real vendor
adapters. It exists so that Flauz builds have working language models with
zero network, zero entitlement, and zero non-determinism from day one.

## What it provides

### flauz-mock — deterministic echo model (live)

- Registered through the **stable** API `vscode.lm.registerLanguageModelChatProvider`
  (vendored `vscode.d.ts:20851`) under vendor `flauz-mock`, which is also
  declared via the `contributes.languageModelChatProviders` contribution in
  `package.json` (`vendor` + `displayName` are the required fields; schema:
  `src/vs/workbench/contrib/chat/common/languageModels.ts:802-915`). Per the
  d.ts note at `vscode.d.ts:20846`, the contribution and the runtime
  registration MUST stay in sync.
- Serves exactly one model: `echo-1` (`Flauz Mock Echo`, family `flauz-echo`,
  version `1`, 8192 max input / 4096 max output tokens, no capabilities).
- Every response is the fixed string `flauz-mock echo: <text of the LAST
  User-role message>`, streamed in deterministic word-grouped chunks (max 3
  words per chunk; chunks concatenate byte-for-byte back to the full string).
  No user text → `flauz-mock echo: (empty prompt)`. Unknown model ids still
  echo (deterministic, never throws in v0).
- `provideTokenCount` returns a character-count approximation (documented
  deterministic stand-in for a real tokenizer).
- Cancellation is honored between chunks: the provider checks
  `token.isCancellationRequested` before every `progress.report` and stops
  early.

### Vendor stubs — design only (NOT live)

`src/vendors/codex.ts`, `src/vendors/claude.ts`, `src/vendors/qwen.ts` export
frozen, plain-data `VendorPlan` literals (`flauz-codex`, `flauz-claude`,
`flauz-qwen`) describing the registration a future adapter WOULD make:
vendor, display name, 1-2 model entries, and a pricing envelope. **STUB —
design shape only (Wave 3 Lane F): no network calls, no registration, no
entitlement.** Real adapters are future work (see the Lane F delivery REPORT
§GAPS-AND-SKIPS).

## Activation (lazy on purpose)

The only activation event is `onLanguageModelChatProvider:flauz-mock` — the
event the editor emits when a consumer actually needs a model of that vendor
(generated by the `languageModelChatProviders` contribution point,
`languageModels.ts:910-914`). The extension therefore costs **zero** startup
work until someone selects a flauz-mock model, per PERFORMANCE-PLAN §2.1
(activation-event discipline). `activate()` only registers the provider and
pushes its disposable onto `context.subscriptions`.

## API posture (DL-4: stable APIs only)

- `enabledApiProposals` is `[]`. The provider API
  (`LanguageModelChatProvider`, `lm.registerLanguageModelChatProvider`) is
  stable at the pinned upstream revision.
- The **pricing envelope** on the vendor stubs is structurally typed after
  the *proposed* `languageModelPricing` API's optional fields
  (input/output/cache/long-context costs, priceCategory, category — see
  `src/vendors/types.ts`). That proposal is **NOT enabled** and nothing from
  it is referenced at runtime; the vendored
  `vscode-dts/vscode.proposed.languageModelPricing.d.ts` is included in the
  tsconfig purely so the compile-time shape is checked against the real
  upstream declaration.

## Toolchain constraints

Node ≥ 23.6 runs the `.ts` sources directly via type stripping, so the code
is ESM-only and limited to **erasable** TypeScript syntax (no enums, no
namespaces, no parameter properties; relative imports use explicit `.ts`
extensions; `import type` for type-only imports). Enum-backed API values
(`LanguageModelChatMessageRole.User === 1`, `LanguageModelChatToolMode.Auto
=== 1`) are pinned as documented number constants instead.

Runtime tests of `src/extension.ts` (which value-imports `vscode`) use
`node:module` `registerHooks` to redirect the `vscode` specifier to
`test/harness/vscode-mock-module.ts` (see `test/harness/vscode-redirect.ts`).

## Running the checks

No install, no build. TypeScript is intentionally only a declared
devDependency; use the workspace binary:

```
/home/z/my-project/node_modules/.bin/tsc --noEmit -p /home/z/my-project/Flauz/extensions/flauz-models/tsconfig.json

node --test /home/z/my-project/Flauz/extensions/flauz-models/test/extension.test.ts \
          /home/z/my-project/Flauz/extensions/flauz-models/test/mockProvider.test.ts \
          /home/z/my-project/Flauz/extensions/flauz-models/test/vendors.test.ts
```

Expected: tsc exit 0; 12 tests, 12 pass, 0 fail. (The `npm test` script
`node --test test/*.test.ts` is the in-directory convenience form. A bare
`node --test test/` directory argument is NOT understood by Node 24.21 — it
is treated as a module path — hence the glob.)

## Packaging (CI-side)

`package.json` points `main` at `./dist/extension.js`, which does not exist
in-repo (`dist/` is gitignored). Producing the esbuild ESM bundle for the
flauz built-in collection is CI-side work, same as the other Flauz built-in
extensions.
